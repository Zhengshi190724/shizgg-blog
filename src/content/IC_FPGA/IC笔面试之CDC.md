为什么需要跨时钟域的处理？答：降低亚稳态发生的概率！
## 几种组合

单bit数据、多bit数据；慢速时钟域向快速时钟域、快速时钟域向慢速时钟域；两两组合。
- 单bit CDC（快到慢、慢到快、速度比较）
	- 处理方法：脉冲同步法、脉冲展宽同步法、脉冲监测反转法……
- 多bit CDC
	- 处理方法：格雷码同步、多bit握手同步、Dmux、异步FIFO、异步RAM
## 亚稳态

- 为什么RTL代码编写时无需考虑亚稳态？**答**：VIVADO综合工具对于**同步逻辑**已经实现了建立时间和保持时间的约束。
- 若data不满足触发器的建立保持时间，在异步复位时时序不满足（恢复/移除时间），Q输出端会在0/1之间来回震荡，后续稳定的电平同样为0/1不定。
- 定义：触发器无法在某个规定时间内达到一个可确定的状态：触发器的输入电压采样时间过短，则触发器需要化很长时间来实现输出逻辑达到标准电平，在这段时间里输出端在高低电平间处于震荡状态，而不是等于理想值。也就是说，电路处于中间态的时间变长，电路“反应”迟钝，这就是亚稳态。
- **亚稳态无法完全消除！只能避免由于亚稳态造成的逻辑问题！**
- 异步时钟网络由于没有统一的时钟网络，因此异步时钟网络没有时钟偏斜的问题！（合理分配时钟域，降低整体系统功耗）

> MTBF：系统发送一次亚稳态引起的故障之间的平均时间。MTBF越长，系统越可靠！

## 建立时间与保持时间

#### 建立时间

- 建立时间：在时钟的有效沿到来之前，数据的输入端信号必须保持稳定的最短时间。
- 满足数据路径 < 时钟路径
	- `Tclk1 + Tco + Tdata + Tsu < Tperiod + Tclk2`
	- `Tco + Tdata + Tsu < Tperiod + Tckew`
	- 建立时间裕量：`Tsu_Slack = Tperiod + Tckew - Tco - Tdata - Tsu`
- 解决建立时间违例（$Tsu_{Slack} < 0$）
	1. 降低主频，增大时钟周期；（缺点：影响性能）
	2. 增加Tclk2的路径延迟、减小Tclk1的路径延迟；
	3. 减小Tsu（使用更高级的触发器路径）；
	4. **减小Tcomb（插入流水线）。**
### 保持时间

- 保持时间：在时钟的有效沿到来之后，数据的输入端信号必须保持稳定的最短时间。
