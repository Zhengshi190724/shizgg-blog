# 一、先理解 Verilog 和 SystemVerilog 验证平台的区别

你之前学习 Verilog 时，主要接触的是：

```verilog
module
always
assign
reg
wire
```

这些内容主要用于描述硬件。

现在代码中又出现了：

```systemverilog
class
new
randomize
virtual interface
task
```

这些主要用于编写验证平台，不表示实际硬件。

可以先做如下区分：

|结构|作用|是否可以综合为硬件|
|---|---|--:|
|`module`|描述硬件或顶层连接|通常可以|
|`interface`|将一组相关信号封装在一起|部分可以|
|`class`|创建验证对象|不可以|
|`transaction`|描述一组测试数据|不可以|
|`driver`|把测试数据转换成引脚信号|不可以|
|`tb_top`|连接 DUT 和验证组件|不可以|

这里真正的设计模块只有：

```systemverilog
module counter
```

其他内容主要用于验证 `counter`。

# 二、counter_if.sv：接口文件

代码：

```systemverilog
interface counter_if(input logic clk);

    logic       load_valid;
    logic [3:0] load_value;

endinterface
```

## 1. interface 是什么

`interface` 可以理解为“一组相关信号的集合”。

如果不使用 interface，driver 可能需要分别保存很多信号：

```systemverilog
virtual logic       clk;
virtual logic       load_valid;
virtual logic [3:0] load_value;
```

使用 interface 后，可以把这些信号封装起来：

```systemverilog
counter_if
```

接口内部包含：

```systemverilog
clk
load_valid
load_value
```

这样 driver 只需要拿到一个 interface，就可以访问里面所有信号。

---

## 2. 时钟为什么写在括号中

```systemverilog
interface counter_if(input logic clk);
```

说明实例化 interface 时，需要给它连接一个时钟。

在 `tb_top.sv` 中：

```systemverilog
counter_if dutif(clk);
```

含义是：

- 创建一个名为 `dutif` 的 interface 实例；
    
- 将 `tb_top` 中的 `clk` 连接给 `dutif.clk`。
    

所以后面 driver 可以写：

```systemverilog
@(posedge vif.clk)
```

通过 interface 访问顶层时钟。

---

## 3. interface 和 module 的实例化方式相似

模块实例化：

```systemverilog
counter u_counter (...);
```

接口实例化：

```systemverilog
counter_if dutif(clk);
```

它们都属于仿真开始时就存在的静态层次结构。

---

## 4. 当前接口的一个问题

接口信号没有初始化：

```systemverilog
logic       load_valid;
logic [3:0] load_value;
```

`logic` 是四状态变量，初始值默认为：

```text
X
```

因此，在 driver 第一次赋值前，波形中会看到：

```text
load_valid = X
load_value = X
```

可以在 `tb_top` 中初始化：

```systemverilog
initial begin
    dutif.load_valid = 1'b0;
    dutif.load_value = 4'd0;
end
```

# 三、transaction.sv：事务数据

代码：

```systemverilog
class transaction;

    rand logic       load_valid;
    rand logic [3:0] load_value;

endclass
```

## 1. class 是什么

`class` 是 SystemVerilog 验证中的动态对象。

它与 `module` 的主要区别是：

```text
module：仿真开始时实例就固定存在
class ：可以在仿真过程中使用 new() 动态创建
```

例如：

```systemverilog
transaction tr;
```

这里只声明了一个句柄，暂时没有创建对象。

类似于 C++ 中的指针：

```text
tr 当前是 null
```

执行：

```systemverilog
tr = new();
```

才真正创建了一个 transaction 对象。

---

## 2. transaction 表示什么

这里一个 transaction 表示一次对计数器的输入操作：

```systemverilog
load_valid
load_value
```

例如，某次随机结果可能是：

```text
load_valid = 1
load_value = 12
```

表示希望计数器加载数值 12。

另一次可能是：

```text
load_valid = 0
load_value = 7
```

此时 `load_value` 实际不会被 DUT 使用，因为 `load_valid=0`，计数器会执行加一操作。

---

## 3. rand 的含义

```systemverilog
rand logic load_valid;
```

表示调用 `randomize()` 时，对 `load_valid` 进行随机化。

```systemverilog
rand logic [3:0] load_value;
```

表示随机产生 0～15。

在没有约束时：

```text
load_valid = 0 或 1
load_value = 0～15
```

总共有：

```text
2 × 16 = 32
```

种组合。理想情况下，每种组合的概率都是：

```text
1/32
```

`rand logic` 在随机化时正常会生成 0 和 1，而不是随机生成 `X` 或 `Z`。

# 四、counter.sv：待验证设计 DUT

代码整理后如下：

```systemverilog
module counter (
    input  logic       resetn,
    input  logic       clk,
    input  logic [3:0] load_value,
    input  logic       load_valid,
    output logic [3:0] q
);

    always_ff @(posedge clk or negedge resetn) begin
        if (!resetn)
            q <= 4'd0;
        else if (load_valid)
            q <= load_value;
        else
            q <= q + 1;
    end

endmodule
```

这是一个 4 位计数器。

---

## 1. always_ff

```systemverilog
always_ff @(posedge clk or negedge resetn)
```

`always_ff` 是 SystemVerilog 专门用于描述触发器的结构。

它和你在 Verilog 中写的：

```verilog
always @(posedge clk or negedge resetn)
```

作用基本相同，但 `always_ff` 能让工具进行更严格的检查。

例如，工具会检查变量 `q` 是否被多个过程同时赋值。

---

## 2. 低有效异步复位

```systemverilog
if (!resetn)
    q <= 4'd0;
```

`resetn` 末尾的 `n` 一般表示低有效：

```text
resetn = 0：复位有效
resetn = 1：正常工作
```

敏感列表中包含：

```systemverilog
negedge resetn
```

表示 `resetn` 从 1 变成 0 时，不需要等待时钟，立即执行复位。

---

## 3. 工作逻辑

当不处于复位状态时：

```systemverilog
else if (load_valid)
    q <= load_value;
else
    q <= q + 1;
```

对应关系为：

|`resetn`|`load_valid`|下一个 `q`|
|--:|--:|---|
|0|任意值|0|
|1|1|`load_value`|
|1|0|`q + 1`|

例如：

```text
当前 q = 5
load_valid = 0
```

下一个时钟上升沿：

```text
q = 6
```

如果：

```text
当前 q = 5
load_valid = 1
load_value = 12
```

下一个时钟上升沿：

```text
q = 12
```

由于 `q` 只有 4 位，最大值为 15：

```text
15 + 1 → 0
```

这是自然溢出，形成模 16 计数器。

# 五、driver.sv：重点解析

代码整理后如下：

```systemverilog
class driver;

    virtual counter_if vif;
    transaction tr;

    function new(input virtual counter_if vif);
        this.vif = vif;
    endfunction

    task run(int n = 10);

        for (int i = 0; i < n; i++) begin

            tr = new();

            assert(tr.randomize());

            $display(
                "tr.load_valid=%0d, tr.load_value=%0d",
                tr.load_valid,
                tr.load_value
            );

            @(posedge vif.clk) begin
                vif.load_valid <= tr.load_valid;
                vif.load_value <= tr.load_value;
            end

        end

    endtask

endclass
```

driver 的主要任务是：

```text
创建 transaction
→ 随机化 transaction
→ 等待时钟
→ 将 transaction 中的数据驱动到 interface
```

下面逐行解释。

---

## 1. 声明 driver 类

```systemverilog
class driver;
```

这只是定义一种类型，并没有创建实际对象。

类似于定义一个模板：

```text
driver 类规定了 driver 对象有哪些变量和方法
```

在 `tb_top` 中执行：

```systemverilog
driver my_driver;
```

只是声明句柄。

执行：

```systemverilog
my_driver = new(dutif);
```

才真正创建 driver 对象。

---

## 2. virtual interface

```systemverilog
virtual counter_if vif;
```

这是整个代码中最关键的新概念之一。

### 为什么要使用 virtual interface

`driver` 是 class，而 `counter_if dutif` 是静态 interface 实例。

class 不能直接通过普通层次连接去连接硬件信号，因此需要使用：

```systemverilog
virtual interface
```

它相当于一个指向实际 interface 实例的句柄。

关系是：

```text
vif  ──────────→  tb_top.dutif
虚接口句柄          实际接口实例
```

因此 driver 中访问：

```systemverilog
vif.load_valid
```

实际上访问的是：

```systemverilog
tb_top.dutif.load_valid
```

访问：

```systemverilog
vif.clk
```

实际上访问的是：

```systemverilog
tb_top.dutif.clk
```

---

## 3. virtual 不会创建新的信号

需要注意：

```systemverilog
virtual counter_if vif;
```

并没有复制一份 interface，也没有创建新的 `load_valid`。

它只是保存对某个 interface 实例的引用。

类似于：

```text
dutif 是实际房间
vif 是这间房间的钥匙
```

driver 通过 `vif` 操作的就是 `dutif` 中的真实信号。

---

## 4. transaction 句柄

```systemverilog
transaction tr;
```

这里只创建一个 transaction 类型的句柄。

此时：

```text
tr = null
```

它还没有指向任何实际 transaction 对象。

---

## 5. 构造函数 new

```systemverilog
function new(input virtual counter_if vif);
    this.vif = vif;
endfunction
```

这是 driver 类的构造函数。

创建 driver 时：

```systemverilog
my_driver = new(dutif);
```

实际调用：

```systemverilog
driver::new(dutif)
```

传入的 `dutif` 会赋给 driver 内部的 `vif`。

---

## 6. this.vif 和 vif

构造函数中有两个同名的 `vif`：

```systemverilog
function new(input virtual counter_if vif);
    this.vif = vif;
endfunction
```

左侧：

```systemverilog
this.vif
```

表示当前 driver 对象内部的成员变量。

右侧：

```systemverilog
vif
```

表示构造函数的输入参数。

因此：

```systemverilog
this.vif = vif;
```

表示：

```text
把外面传进来的实际接口句柄
保存到当前 driver 对象内部
```

类似于：

```systemverilog
class example;

    int value;

    function new(int value);
        this.value = value;
    endfunction

endclass
```

---

## 7. 为什么 new 是 function

```systemverilog
function new(...);
```

构造函数必须写为 function。

SystemVerilog 中：

|类型|能否消耗仿真时间|
|---|--:|
|`function`|不能|
|`task`|可以|

构造对象和保存 interface 句柄不需要等待时间，因此使用 function。

function 中不能使用：

```systemverilog
#10;
@(posedge clk);
wait(...);
```

---

## 8. run 为什么是 task

```systemverilog
task run(int n = 10);
```

`run()` 中包含：

```systemverilog
@(posedge vif.clk)
```

它需要等待时钟，会消耗仿真时间，所以必须使用 task，不能使用 function。

参数：

```systemverilog
int n = 10
```

表示默认产生 10 个 transaction。

调用：

```systemverilog
my_driver.run();
```

产生 10 次随机激励。

调用：

```systemverilog
my_driver.run(20);
```

产生 20 次随机激励。

---

## 9. for 循环

```systemverilog
for (int i = 0; i < n; i++) begin
```

这里的写法是 SystemVerilog 相比 Verilog 的改进。

Verilog 中经常需要提前声明：

```verilog
integer i;

for (i = 0; i < n; i = i + 1)
```

SystemVerilog 可以直接写：

```systemverilog
for (int i = 0; i < n; i++)
```

变量 `i` 只在该循环中有效。

---

## 10. 每次循环创建一个 transaction

```systemverilog
tr = new();
```

每次循环都会创建一个新的 transaction 对象。

第 1 次循环：

```text
tr → transaction对象1
```

第 2 次循环：

```text
tr → transaction对象2
```

旧对象如果没有其他句柄指向它，最终会由仿真器自动回收。

---

## 11. randomize

```systemverilog
assert(tr.randomize());
```

`randomize()` 对 transaction 中带 `rand` 的变量进行随机化：

```systemverilog
rand logic       load_valid;
rand logic [3:0] load_value;
```

相当于产生：

```text
load_valid = 随机的0或1
load_value = 随机的0～15
```

`randomize()` 会返回一个布尔结果：

```text
1：随机化成功
0：随机化失败
```

所以使用：

```systemverilog
assert(tr.randomize());
```

检查随机化是否成功。

更完整的写法是：

```systemverilog
assert (tr.randomize())
else
    $fatal("Transaction randomization failed");
```

这样随机化失败时，能够明确停止仿真。

---

## 12. 打印随机结果

```systemverilog
$display(
    "tr.load_valid=%0d, tr.load_value=%0d",
    tr.load_valid,
    tr.load_value
);
```

例如输出：

```text
tr.load_valid=1, tr.load_value=12
tr.load_valid=0, tr.load_value=4
tr.load_valid=1, tr.load_value=3
```

`%0d` 表示按十进制输出，并尽量不保留多余宽度。

---

## 13. 等待时钟上升沿

```systemverilog
@(posedge vif.clk)
```

表示暂停当前 task，直到检测到：

```text
vif.clk：0 → 1
```

因为 `vif` 指向 `tb_top.dutif`，而 `dutif.clk` 连接顶层 `clk`，所以实际上等待的是：

```systemverilog
@(posedge tb_top.clk)
```

---

## 14. 驱动 interface

```systemverilog
vif.load_valid <= tr.load_valid;
vif.load_value <= tr.load_value;
```

把 transaction 中的随机数据送给 interface：

```text
tr.load_valid  → vif.load_valid
tr.load_value  → vif.load_value
```

interface 又与 DUT 连接，因此最终：

```text
transaction
    ↓
driver
    ↓
dutif.load_valid / dutif.load_value
    ↓
counter.load_valid / counter.load_value
```

---

## 15. 为什么使用非阻塞赋值

代码使用：

```systemverilog
<=
```

而不是：

```systemverilog
=
```

非阻塞赋值会把更新安排到当前时间步的 NBA 区域。

不过，这段代码存在一个重要的时序现象：

```systemverilog
@(posedge vif.clk)
vif.load_valid <= tr.load_valid;
```

与此同时，DUT 也在：

```systemverilog
always_ff @(posedge clk)
```

采样输入。

因此在同一个上升沿：

1. DUT 先基于旧的 `load_valid/load_value` 计算；
    
2. driver 再通过非阻塞赋值更新新数据；
    
3. 新数据要到下一个上升沿才被 DUT 使用。
    

也就是说：

```text
当前上升沿：driver 发出新激励
下一个上升沿：DUT 采样该激励
```

这不是语法错误，但容易让初学者误以为 DUT 会在当前上升沿立即使用新值。

---

## 16. 推荐初学阶段改成下降沿驱动

可以让 driver 在下降沿改变输入：

```systemverilog
@(negedge vif.clk) begin
    vif.load_valid <= tr.load_valid;
    vif.load_value <= tr.load_value;
end
```

这样：

```text
下降沿：driver 改变输入
上升沿：DUT 采样输入
```

输入信号有半个周期的稳定时间，更容易理解，也能避免竞争问题。

推荐写法：

```systemverilog
task run(int n = 10);

    for (int i = 0; i < n; i++) begin

        tr = new();

        assert (tr.randomize())
        else
            $fatal("Randomization failed");

        @(negedge vif.clk);

        vif.load_valid <= tr.load_valid;
        vif.load_value <= tr.load_value;

        $display(
            "time=%0t load_valid=%0d load_value=%0d",
            $time,
            tr.load_valid,
            tr.load_value
        );

    end

endtask
```

以后学习到 `clocking block` 后，通常会使用 clocking block 更规范地处理采样与驱动竞争。

# 六、tb_top.sv：重点解析

原代码整理后大致如下：

```systemverilog
module tb_top;

    logic       clk;
    logic       rstn;
    logic [3:0] out;

    counter_if dutif(clk);

    driver my_driver;

    initial begin
        my_driver = new(dutif);

        repeat (2) @(posedge clk);
        @(posedge rstn);
        repeat (5) @(posedge clk);

        my_driver.run(20);
    end

    initial begin
        clk = 1'b0;
        forever #5 clk = ~clk;
    end

    initial begin
        rstn = 1'b1;
        repeat (2) @(posedge clk);

        rstn = 1'b0;
        repeat (5) @(posedge clk);

        rstn = 1'b1;
        repeat (50) @(posedge clk);

        $finish;
    end

    counter u_counter (
        .resetn     (rstn),
        .clk        (clk),
        .load_valid (dutif.load_valid),
        .load_value (dutif.load_value),
        .q          (out)
    );

endmodule
```

`tb_top` 的作用是：

```text
创建时钟
产生复位
实例化 interface
创建 driver
实例化 DUT
连接 DUT 和 interface
启动测试
结束仿真
```

---

## 1. 顶层 module

```systemverilog
module tb_top;
```

验证平台顶层通常没有输入输出端口。

因为时钟、复位和激励都由 testbench 自己产生。

---

## 2. 顶层信号

```systemverilog
logic       clk;
logic       rstn;
logic [3:0] out;
```

含义：

```text
clk  ：时钟
rstn ：低有效复位
out  ：DUT计数输出
```

这里使用 `logic`，它可以代替很多 Verilog 中 `reg` 的使用场景。

---

## 3. 创建实际 interface

```systemverilog
counter_if dutif(clk);
```

这里创建了一个真实的 interface 实例：

```text
类型：counter_if
实例名：dutif
```

并把顶层时钟 `clk` 传入 interface。

因此：

```systemverilog
dutif.clk
```

就是顶层的：

```systemverilog
clk
```

---

## 4. 声明 driver 句柄

```systemverilog
driver my_driver;
```

此时只是声明一个句柄：

```text
my_driver = null
```

还没有实际 driver 对象。

必须调用：

```systemverilog
my_driver = new(dutif);
```

才能使用：

```systemverilog
my_driver.run(20);
```

如果没有执行 `new()`，直接调用 `run()`，会出现空句柄错误。

---

# 七、tb_top 中第一个 initial：启动 driver

```systemverilog
initial begin
    my_driver = new(dutif);

    repeat (2) @(posedge clk);
    @(posedge rstn);
    repeat (5) @(posedge clk);

    my_driver.run(20);
end
```

逐句分析。

---

## 1. 创建 driver

```systemverilog
my_driver = new(dutif);
```

调用 driver 的构造函数：

```systemverilog
function new(input virtual counter_if vif);
    this.vif = vif;
endfunction
```

建立关系：

```text
my_driver.vif → tb_top.dutif
```

从此以后 driver 可以通过：

```systemverilog
vif.load_valid
vif.load_value
vif.clk
```

访问 interface 中的信号。

---

## 2. 等待两个时钟

```systemverilog
repeat (2) @(posedge clk);
```

表示连续等待两个时钟上升沿。

相当于：

```systemverilog
@(posedge clk);
@(posedge clk);
```

假设时钟周期是 10 ns，上升沿发生在：

```text
5 ns、15 ns、25 ns、35 ns……
```

那么 `repeat(2)` 会依次等待：

```text
5 ns
15 ns
```

然后继续执行。

---

## 3. 等待复位释放

```systemverilog
@(posedge rstn);
```

表示等待 `rstn` 从 0 变成 1。

因为 `rstn` 是低有效复位：

```text
rstn = 0：正在复位
rstn = 1：复位释放
```

所以这句相当于：

```text
等待 DUT 离开复位状态
```

---

## 4. 复位释放后再等待五个时钟

```systemverilog
repeat (5) @(posedge clk);
```

复位释放后，不立即发送激励，而是再等待五个时钟。

这通常用于给 DUT 一些初始化时间。

对于这个简单计数器来说，并非必须，但在复杂芯片验证中很常见。

---

## 5. 产生 20 次随机激励

```systemverilog
my_driver.run(20);
```

进入 driver 的 `run()` task，循环 20 次。

每次进行：

```text
创建transaction
→ 随机化
→ 打印
→ 等待时钟
→ 驱动interface
```

---

# 八、tb_top 中第二个 initial：产生时钟

```systemverilog
initial begin
    clk = 1'b0;
    forever #5 clk = ~clk;
end
```

仿真开始时：

```text
clk = 0
```

之后每隔 5 个时间单位翻转一次：

```text
0 → 1 → 0 → 1
```

如果 timescale 是：

```systemverilog
`timescale 1ns/1ps
```

则：

```text
#5 = 5 ns
```

波形为：

```text
时间：0    5    10   15   20   25
clk ：0 ───1────0────1────0────1
```

完整时钟周期为：

```text
5 ns + 5 ns = 10 ns
```

时钟频率为：

```text
1 / 10 ns = 100 MHz
```

`forever` 是无限循环：

```systemverilog
forever #5 clk = ~clk;
```

它不会自行结束，整个仿真最终由 `$finish` 结束。

---

# 九、tb_top 中第三个 initial：产生复位

原代码：

```systemverilog
initial begin
    rstn = 1;

    repeat (2) @(posedge clk);

    rstn = 0;

    repeat (5) @(posedge clk);

    rstn = 1;

    repeat (50) @(posedge clk);

    $finish;
end
```

执行过程：

```text
仿真开始：rstn = 1，未复位
等待2个时钟
rstn = 0，进入复位
等待5个时钟
rstn = 1，退出复位
等待50个时钟
结束仿真
```

---

## 当前复位写法的问题

仿真刚开始时：

```systemverilog
rstn = 1;
```

意味着 DUT 一开始没有进入复位。

而 `q` 没有初值，所以最初可能是：

```text
q = X
```

等待两个时钟后才拉低复位。

更规范的写法是让 DUT 从 0 时刻开始就处于复位：

```systemverilog
initial begin
    rstn = 1'b0;

    repeat (5) @(posedge clk);

    rstn = 1'b1;

    repeat (50) @(posedge clk);

    $finish;
end
```

这样从仿真开始：

```text
rstn = 0
q = 0
```

波形更清晰。

---

## 更稳妥地在下降沿释放复位

如果在时钟上升沿同一时刻修改 `rstn`，可能产生仿真调度竞争。

推荐：

```systemverilog
initial begin
    rstn = 1'b0;

    repeat (5) @(posedge clk);

    @(negedge clk);
    rstn = 1'b1;

    repeat (50) @(posedge clk);

    $finish;
end
```

在下降沿释放复位后，距离下一个上升沿还有半个周期，DUT 可以稳定地检测到复位已经释放。

# 十、DUT 实例化和信号连接

```systemverilog
counter u_counter (
    .resetn     (rstn),
    .clk        (clk),
    .load_valid (dutif.load_valid),
    .load_value (dutif.load_value),
    .q          (out)
);
```

左边是 counter 模块的端口名：

```systemverilog
.resetn
.clk
.load_valid
.load_value
.q
```

右边是 testbench 中的信号：

```systemverilog
rstn
clk
dutif.load_valid
dutif.load_value
out
```

连接关系：

```text
tb_top.rstn               → u_counter.resetn
tb_top.clk                → u_counter.clk
tb_top.dutif.load_valid   → u_counter.load_valid
tb_top.dutif.load_value   → u_counter.load_value
u_counter.q               → tb_top.out
```

注意，当前 interface 只封装了输入激励：

```text
load_valid
load_value
```

输出 `q` 没有放在 interface 中，而是直接连接给：

```systemverilog
logic [3:0] out;
```

对于初学示例没有问题。更完整的验证平台通常也会把 `q` 放入 interface，方便 monitor 采样。

# 十一、所有 initial 是并行执行的

`tb_top` 中有三个 `initial`：

```systemverilog
initial begin
    // driver
end

initial begin
    // clock
end

initial begin
    // reset
end
```

它们不是依次执行，而是在仿真 0 时刻同时开始。

可以理解为三个并行线程：

```text
线程1：创建driver并等待启动条件
线程2：持续产生时钟
线程3：产生复位并最终结束仿真
```

执行关系大致是：

```text
时间0：
  时钟线程：clk=0
  复位线程：设置rstn
  driver线程：创建my_driver，然后等待时钟

之后：
  时钟不断翻转
  复位线程控制rstn
  driver线程等待复位释放后发送激励
```

这是 HDL 与普通 C 程序非常重要的区别。

C 程序通常从上向下顺序执行，而 Verilog/SystemVerilog 中多个 `initial`、`always` 是并行执行的。

---

# 十二、一次 transaction 的完整数据流

假设随机得到：

```text
tr.load_valid = 1
tr.load_value = 12
```

driver 执行：

```systemverilog
vif.load_valid <= 1;
vif.load_value <= 12;
```

因为：

```text
vif → dutif
```

所以：

```text
dutif.load_valid = 1
dutif.load_value = 12
```

又因为 interface 和 DUT 相连：

```text
u_counter.load_valid = 1
u_counter.load_value = 12
```

DUT 在下一个上升沿执行：

```systemverilog
else if (load_valid)
    q <= load_value;
```

所以：

```text
q = 12
out = 12
```

如果下一次随机得到：

```text
load_valid = 0
load_value = 7
```

DUT 不会使用 7，而是执行：

```systemverilog
q <= q + 1;
```

所以：

```text
q = 13
```

---

# 十三、为什么波形中 load_value 每周期都有随机值

即使：

```text
load_valid = 0
```

driver 仍然会执行：

```systemverilog
vif.load_value <= tr.load_value;
```

所以 `load_value` 依然变化。

但是 DUT 中：

```systemverilog
else if (load_valid)
    q <= load_value;
else
    q <= q + 1;
```

当 `load_valid=0` 时，`load_value` 被忽略。

因此：

```text
load_valid = 0 时，load_value 的值没有实际功能意义
```

它只是 transaction 中随机产生并被 driver 驱动出来了。

# 十四、推荐的初学版 driver.sv

为了让时序更直观，建议下降沿驱动：

```systemverilog
class driver;

    // 指向tb_top中实际counter_if实例的虚接口句柄
    virtual counter_if vif;

    // transaction对象句柄
    transaction tr;

    // 构造函数：接收并保存interface
    function new(input virtual counter_if vif);
        this.vif = vif;
    endfunction

    // 产生n组随机激励
    task run(int n = 10);

        for (int i = 0; i < n; i++) begin

            // 创建新的transaction对象
            tr = new();

            // 随机化transaction中的rand变量
            assert (tr.randomize())
            else
                $fatal("Transaction randomization failed");

            // 在下降沿驱动，保证下一个上升沿之前输入稳定
            @(negedge vif.clk);

            vif.load_valid <= tr.load_valid;
            vif.load_value <= tr.load_value;

            $display(
                "[%0t] load_valid=%0b, load_value=%0d",
                $time,
                tr.load_valid,
                tr.load_value
            );

        end

        // 激励结束后恢复空闲状态
        @(negedge vif.clk);
        vif.load_valid <= 1'b0;
        vif.load_value <= 4'd0;

    endtask

endclass
```

# 十五、推荐的初学版 tb_top.sv

```systemverilog
`timescale 1ns/1ps

module tb_top;

    logic       clk;
    logic       rstn;
    logic [3:0] out;

    // 创建interface实例，并连接时钟
    counter_if dutif(clk);

    // driver对象句柄
    driver my_driver;

    //==================================================
    // 时钟产生：周期10ns
    //==================================================
    initial begin
        clk = 1'b0;
        forever #5 clk = ~clk;
    end

    //==================================================
    // 初始化interface信号，防止仿真开始出现X
    //==================================================
    initial begin
        dutif.load_valid = 1'b0;
        dutif.load_value = 4'd0;
    end

    //==================================================
    // 产生低有效复位
    //==================================================
    initial begin
        rstn = 1'b0;

        repeat (5) @(posedge clk);

        // 在下降沿释放复位
        @(negedge clk);
        rstn = 1'b1;
    end

    //==================================================
    // 创建并启动driver
    //==================================================
    initial begin
        my_driver = new(dutif);

        // 等待复位释放
        @(posedge rstn);

        // 再等待两个时钟
        repeat (2) @(posedge clk);

        // 产生20组随机激励
        my_driver.run(20);

        // 等待几个周期再结束，确保最后一组数据被DUT采样
        repeat (5) @(posedge clk);

        $finish;
    end

    //==================================================
    // 打印信号
    //==================================================
    initial begin
        $monitor(
            "[%0t] rstn=%0b valid=%0b value=%0d q=%0d",
            $time,
            rstn,
            dutif.load_valid,
            dutif.load_value,
            out
        );
    end

    //==================================================
    // 实例化待验证计数器
    //==================================================
    counter u_counter (
        .resetn     (rstn),
        .clk        (clk),
        .load_value (dutif.load_value),
        .load_valid (dutif.load_valid),
        .q          (out)
    );

endmodule
```

    ↓

    ↓

# 十七、现阶段最需要掌握的几个概念

按照重要性，建议先掌握：

1. **class 是动态对象，不是硬件。**
    
2. **声明句柄不等于创建对象，必须调用 `new()`。**
    
3. **transaction 表示一组抽象测试数据。**
    
4. **driver 将 transaction 转换为实际引脚时序。**
    
5. **interface 封装一组相关信号。**
    
6. **virtual interface 让 class 可以访问实际 interface。**
    
7. **function 不允许消耗时间，task 可以等待时钟。**
    
8. **多个 initial 和 always 是并行运行的。**
    
9. **在上升沿驱动输入时，要注意 DUT 同时采样造成的一周期延迟。**
    
10. **logic 未初始化时默认是 X。**
    

这五个文件的核心可以浓缩成一句话：

```text
tb_top 创建 driver 和实际 interface，
把 interface 传给 driver，
driver 随机创建 transaction，
再通过 virtual interface 将 transaction 驱动给 counter。
```
